# SmsForwarder 通知接收插件开发计划

## 1. 目标

开发 Catrace 插件 `smsforwarder-notify`，接收 Android 端 SmsForwarder 发出的 App 通知 Webhook，并在 Windows 上显示 Catrace Toast。

首版定位：同一局域网内的个人自用通知转发。

数据链路：

```text
Android 通知
  -> SmsForwarder 通知监听与规则
  -> HTTP POST Webhook
  -> Catrace 插件 Node sidecar
  -> stdout JSONL publish
  -> Catrace Toast
```

## 2. 范围

### MVP 包含

- 局域网 HTTP Webhook 接收服务
- 固定路径和 Token 鉴权
- 解析 SmsForwarder JSON 请求
- 显示 App 名称、通知标题、正文和接收时间
- 相同通知短时间去重
- App 黑名单
- Toast 停留时间配置
- 验证码识别和一键复制
- 设置页显示 Webhook 地址、请求模板、服务状态和最近请求结果
- 手动测试通知
- 请求体大小、字段长度和访问频率限制
- 插件停止时关闭 HTTP 服务

### MVP 不包含

- 公网中继、云服务器或账号系统
- 手机通知撤销同步
- Android 通知操作按钮映射
- 图片、头像、App 图标同步
- Windows 原生通知中心历史同步
- 多设备配对管理
- 双向快捷回复
- 自签 HTTPS 服务

## 3. 已确认约束

- SmsForwarder Webhook 支持 `GET`、`POST`、`PUT`、`PATCH`，本插件只支持 `POST`。
- SmsForwarder 支持自定义请求头，可发送静态 `Authorization: Bearer <token>`。
- SmsForwarder 支持 JSON 消息模板，可直接使用 App 通知变量。
- 局域网明文 HTTP 地址可用，例如 `http://192.168.1.20:17890/webhook`。
- `{{APP_NAME}}` 依赖 SmsForwarder 开启“启动时异步获取已安装 App 列表”；取不到时使用包名。
- `{{TITLE}}` 可能为空；通知标题和正文同时为空时，SmsForwarder 本身可能不转发。
- SmsForwarder 官方文档明确支持 Android 4.4 至 13；Android 14 以上需实机验证。
- Catrace sidecar 可使用 Node 内置 `http` 创建服务，通过 stdout JSONL `op: publish` 发布事件。
- Catrace 可通过事件 `payload.auto_hide_ms` 控制 Toast 停留时间，通过 `dedupeKey` 去重。

## 4. 技术设计

### 4.1 插件结构

```text
smsforwarder-notify/
├── manifest.json
├── settings.mjs
├── ui.mjs
├── background.mjs
├── 开发计划.md
└── runtime/
    └── main.mjs
```

- `manifest.json`：声明 UI、设置页、background、sidecar 和事件类型。
- `runtime/main.mjs`：HTTP 服务、鉴权、校验、限流、去重、验证码提取、事件发布。
- `settings.mjs`：配置、连接说明、模板复制、服务状态、测试入口。
- `ui.mjs`：Toast 卡片布局和验证码复制按钮。
- `background.mjs`：处理 Toast 按钮回调，将验证码写入系统剪贴板。

### 4.2 默认配置

| 配置键 | 类型 | 默认值 | 说明 |
|---|---|---:|---|
| `enabled` | boolean | `true` | 是否接收通知 |
| `host` | string | `0.0.0.0` | 监听全部网卡；设置页提示安全风险 |
| `port` | number | `17890` | HTTP 端口，范围 1024 至 65535 |
| `path` | string | `/webhook` | Webhook 路径 |
| `token` | string | 首次生成 | 至少 32 字节随机 Token |
| `cardDurationSec` | number | `10` | Toast 停留秒数，0 表示常驻 |
| `dedupeWindowSec` | number | `5` | 相同通知去重窗口 |
| `appBlacklist` | string[] | `[]` | 包名或 App 名称黑名单 |
| `hideSensitiveBody` | boolean | `false` | 隐私模式，仅显示来源和标题 |
| `enableOtpAction` | boolean | `true` | 识别验证码并显示复制按钮 |

配置变化通过 Catrace sidecar `config` 消息下发。端口、host 或 path 变化时，sidecar 平滑重启 HTTP server；启动失败保留旧服务并返回错误状态。

### 4.3 Webhook 接口

请求：

```http
POST /webhook HTTP/1.1
Authorization: Bearer <token>
Content-Type: application/json; charset=utf-8
```

推荐 SmsForwarder 消息模板：

```json
{
  "packageName": "{{PACKAGE_NAME}}",
  "appName": "{{APP_NAME}}",
  "title": "{{TITLE}}",
  "body": "{{MSG}}",
  "receivedAt": "{{RECEIVE_TIME}}",
  "uid": "{{UID}}",
  "device": "[device_mark]",
  "timestamp": "[timestamp]"
}
```

响应：

```json
{"ok":true}
```

错误状态：

- `400`：JSON 或字段格式错误
- `401`：Token 缺失或错误
- `404`：路径错误
- `405`：非 POST 请求
- `413`：请求体过大
- `429`：请求过快
- `500`：内部发布失败

SmsForwarder “响应关键词”可填写：

```text
"ok":true
```

### 4.4 字段标准化

- `packageName`：最多 255 字符；缺失时设为 `unknown`。
- `appName`：最多 100 字符；空值回退到 `packageName`。
- `title`：最多 300 字符；空值回退到 `appName`。
- `body`：最多 4000 字符；Toast 展示时再限制长度。
- `receivedAt`：保留原值；无法解析时使用电脑接收时间。
- `timestamp`：可选。首版不依赖手机时钟做强校验，避免时钟偏差导致丢通知。
- 未知字段忽略，不写入日志。

### 4.5 鉴权与安全

- 默认绑定 `0.0.0.0`，否则手机无法访问；设置页醒目标注仅限可信局域网。
- 使用 Node `crypto.randomBytes(32)` 生成 Token。
- 使用常量时间比较验证 Bearer Token。
- 最大请求体 `64 KiB`。
- 单 IP 默认最多每分钟 120 次请求，超限返回 `429`。
- 只接受 `application/json`。
- 不保存完整通知历史，不把 Token 和通知正文写日志。
- 日志只记录时间、来源 IP、状态码、包名和正文长度。
- 不自动修改 Windows 防火墙；设置页给出手动放行提示。
- 不开放公网使用说明。公网需求另做 TLS 或中继方案。

### 4.6 去重

首版使用内存去重，不落盘：

```text
SHA-256(packageName + title + body + device)
```

- 相同哈希在 `dedupeWindowSec` 内只发布一次。
- 最多保留 500 个哈希，定期清理过期项。
- Catrace `dedupeKey` 使用同一哈希，作为第二层保护。
- 插件重启后允许再次出现，不引入通知内容持久化。

### 4.7 验证码识别

先要求正文或标题含关键词：

```text
验证码|校验码|动态码|verification code|security code|OTP
```

再提取独立的 4 至 8 位数字：

```regex
(?<!\d)\d{4,8}(?!\d)
```

- 命中时 Toast 增加“复制验证码”按钮。
- 按钮事件由 `background.mjs` 调用 `plugin.clipboard.writeText(code)`。
- 首版不自动写剪贴板，避免覆盖用户已有内容。

### 4.8 Toast 事件

```json
{
  "eventType": "smsforwarder-notify.notification",
  "kind": "smsforwarder-notify",
  "title": "微信 · 张三",
  "body": "消息正文",
  "level": "info",
  "actions": [{"id":"copy-otp","label":"复制验证码"}],
  "payload": {
    "packageName": "com.tencent.mm",
    "appName": "微信",
    "receivedAt": "2026-08-07 10:30:00",
    "otp": "123456",
    "auto_hide_ms": 10000
  },
  "dedupeKey": "smsforwarder-notify:<sha256>"
}
```

没有验证码时不提供 action。隐私模式开启时不把正文和验证码放入 Toast payload。

## 5. 设置页设计

设置页分四块：

### 服务状态

- 运行中/未运行
- 实际监听地址和端口
- 本机可用 IPv4 地址列表
- 最近一次成功请求时间
- 最近一次错误摘要
- 已接收、已拒绝、已去重计数

### 连接配置

- 端口
- Webhook 路径
- Token 显示/隐藏
- 重新生成 Token
- Toast 停留时间
- 去重窗口

重新生成 Token 会使手机旧配置立即失效，按钮需要二次确认。

### 过滤与隐私

- App 黑名单，一行一个包名或 App 名称
- 隐私模式
- 验证码按钮开关

### 使用教程

- 四步引导：准备条件、启用插件、配置 SmsForwarder、验证通知链路
- 「配置 SmsForwarder」步骤内**直接内联展示** Webhook URL、Authorization（Key/Value 分开复制）、JSON 消息模板，每一项带复制按钮；成功应答关键字 / Content-Type / Secret 均留空
- 提示开启通知使用权和已安装 App 列表加载
- 提示 Windows 防火墙与 Wi-Fi 客户端隔离问题
- 提供“发送本地测试 Toast”按钮

## 6. 实施步骤

### 阶段 1：协议探针

1. 建立最小 sidecar HTTP server。
2. 接收任意 JSON，输出脱敏日志并返回 `{"ok":true}`。
3. 用 PowerShell `Invoke-RestMethod` 验证局域网监听。
4. 用 SmsForwarder Webhook 测试功能验证真实请求格式。

验收：手机测试请求能到达电脑，SmsForwarder 显示发送成功。

### 阶段 2：MVP 通知链路

1. 完成 `manifest.json` 和事件声明。
2. 完成请求解析、字段标准化和 `op: publish`。
3. 完成基础 `ui.mjs` Toast 卡片。
4. 完成 Token 鉴权、请求体限制和状态码。

验收：微信、短信和普通 App 通知可在 Catrace 弹出；错误 Token 被拒绝。

### 阶段 3：设置与运行状态

1. 完成设置页配置项。
2. 实现配置实时下发和 HTTP server 重启。
3. 实现状态查询、计数和错误显示。
4. 提供 SmsForwarder URL、请求头、模板复制功能。

验收：修改端口、Token、停留时间后无需改代码即可生效。

### 阶段 4：体验与安全

1. 完成短时去重。
2. 完成 App 黑名单和隐私模式。
3. 完成验证码识别及复制按钮。
4. 完成速率限制、敏感日志清理和异常边界处理。

验收：重复通知不刷屏；黑名单不弹；验证码可一键复制；日志无 Token 和正文。

### 阶段 5：实机回归

测试来源：

- 系统短信
- 微信或企业微信
- QQ 或 Telegram
- 邮件客户端
- 下载进度或音乐常驻通知
- 标题为空通知
- 超长正文通知
- 同内容连续通知
- 手机切换 Wi-Fi 后通知
- Catrace 重启、插件禁用再启用

验收：核心通知稳定到达；失败原因可在设置页定位；插件退出后端口释放。

## 7. 测试计划

### 自动测试或脚本验证

- `node --check` 校验所有 `.mjs`。
- 正确 Token + 正确 JSON 返回 `200`。
- 错误 Token 返回 `401`。
- 非 POST 返回 `405`。
- 非 JSON 返回 `400` 或 `415`。
- 超过 `64 KiB` 返回 `413`。
- 超频返回 `429`。
- 缺失字段仍能生成可显示事件。
- 黑名单、隐私模式、验证码提取和去重使用固定输入验证。
- sidecar 收到 `shutdown` 后进程退出且端口释放。

### 手工验收

- 手机与电脑同一 Wi-Fi 时，实际通知端到端延迟目标小于 2 秒。
- Catrace 主窗口关闭但应用仍运行时，Toast 仍可显示。
- Windows 重启后插件可恢复监听。
- Token 不出现在 Catrace 日志和 Toast payload。
- 防火墙未放行时，设置页说明足以定位问题。

## 8. 风险与处理

| 风险 | 处理 |
|---|---|
| Windows 防火墙阻止入站 | 设置页展示端口和排查说明；首版不自动提权改防火墙 |
| Wi-Fi 开启客户端隔离 | 提示改用允许设备互访的网络 |
| 电脑 IP 变化 | 设置页列出当前 IPv4；后续再评估 mDNS 或二维码配对 |
| SmsForwarder 取不到 App 名 | 回退显示包名 |
| 手机厂商杀后台 | 引导用户给 SmsForwarder 自启动和电池白名单 |
| Android 14 以上兼容未知 | 在目标手机实测，不宣称官方未覆盖版本 |
| 局域网 HTTP 明文 | 强制随机 Token；仅建议可信局域网；公网另做安全方案 |
| 通知更新造成重复 | 短时内容哈希去重；完整生命周期同步不纳入 MVP |
| SmsForwarder JSON 转义异常 | 阶段 1 用真实通知验证模板；必要时兼容 form-urlencoded 作为后续补丁 |
| 商业发布授权风险 | 当前方案仅将 SmsForwarder 视为外部兼容客户端，不打包、不修改、不分发其代码或 APK；商业化前单独审查其声明和授权 |

## 9. 完成定义

- SmsForwarder 能用文档中的 URL、Header、JSON 模板完成配置。
- Android 普通 App 通知能稳定显示为 Catrace Toast。
- 未授权请求、超大请求和异常请求不会触发 Toast。
- 重复通知、黑名单通知按配置过滤。
- 验证码通知提供复制按钮。
- 设置修改实时生效，服务状态可观测。
- 插件禁用或退出后 HTTP 端口释放。
- 全部 `.mjs` 通过 `node --check`，端到端实机用例通过。

## 10. 后续版本候选

- mDNS 服务发现和二维码配置
- 多手机独立 Token、设备名和撤销能力
- App 白名单及按 App 设置 Toast 行为
- 手机亮屏时不转发
- 通知分组与批量折叠
- App 图标缓存
- 自托管 HTTPS 或可信中继
- Windows 启动时自动检测 IP 变化
- 双向操作和快捷回复；需要独立 Android 客户端，不依赖 SmsForwarder Webhook
