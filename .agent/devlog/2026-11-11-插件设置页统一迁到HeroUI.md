# 2026-11-11 插件设置页统一迁到 HeroUI

## 会话目标

宿主界面 2026-11 已整体迁到 HeroUI v3 + Tailwind 4，但外部插件的设置页还是 Radix / 手写控件，和宿主插件详情页（久坐提醒）怎么看都不像一家人。本轮把已上架插件的设置页控件统一换成 HeroUI，并让宿主在插件运行时里公开同一份 HeroUI 组件库。

## 完成项

- 宿主 `src/plugins/pluginRuntime.ts` 新增注入 `globalThis.__CATRACE_HEROUI__`（`@heroui/react` 命名空间），与已有的 `__CATRACE_REACT__`、`__CATRACE_RADIX__` 同一处安装；Radix 保留给尚未迁移的卡片。
- 宿主合同测试 `scripts/test-react-plugin-packages.mjs`：提供 `__CATRACE_HEROUI__`、新增「插件模块可以渲染 HeroUI 组件」用例、把写死的 `manifest.version` 断言改成日期格式断言。
- 五个已上架插件的设置页改成 HeroUI：agent-notify、dsh-chat、github-notify、pastedrop、smsforwarder-notify。`ui.mjs` 卡片不动。
- 新增 [HeroUI 设置页约定](../features/shared-ui/hero-ui-settings.md)：运行时合同、控件映射、尺寸与配色约定、布局与测试注意事项。
- 实机验收后第二轮修正：所有数字输入改成 HeroUI 默认 `NumberField`（−/+ 步进、`variant="secondary"` 灰底），补上遗漏 secondary 的文本输入；SmsForwarder 的 `Tabs` 补 `TabListContainer`，恢复 HeroUI 默认的灰色底轨；数字框宽度统一加到 9rem，避免步进按钮挤掉输入区。
- PasteDrop 设置页去掉「保存位置」三选一，固定为桌面 + 资源管理器当前文件夹（PasteDrop 原生行为）：`settings.mjs` 不再读写 `saveScope`，sidecar `workerEnv` 写死 `CATRACE_PD_SAVE_SCOPE='both'`，旧配置里的 `saveScope` 被忽略。
- PasteDrop 的 manifest 描述去掉「（源自独立工具 PasteDrop）」这半句（列表 / 详情仍显示前一句），设置页「保存行为」卡里那行说明删除。
- 实机验收后第三轮（2026-11-12，版本统一 `2026.11.12`）：
  - `ToggleButtonGroup` 按官方 anatomy 补 `ToggleButtonGroupSeparator`（放进除首项外的每个 `ToggleButton`），不然项目之间没有细线，和官网样式不一样。
  - DSH 小窗的「显示项」从一排独立 `ToggleButton` 改成多选 `ToggleButtonGroup`（`selectionMode="multiple"` + `selectedKeys` 受控）：独立 toggle 和旁边的操作按钮外观一样，用户分不清哪些是开关、哪些是按钮。
  - 统一按钮层级：`primary` 只给保存/提交类主操作；`secondary` 给会改状态的动作（安装 Hook、立即拉取、发送测试、添加）；`tertiary` 给查看/预览/刷新/复制/显示隐藏；`danger-soft` 给破坏性动作；确认弹窗最终确认键用 `danger`。预览、测试卡片、刷新状态从 secondary 降到 tertiary。

## 关键取舍与坑

- **用扁平导出，不用复合静态属性**：`Switch.Content` / `Select.Trigger` 这类写法在 Blob 模块里也能用，但插件自己的 Node 单测把组件 stub 成字符串类型时无法构造静态属性；统一 `SwitchRoot` / `SwitchContent` / `SelectRoot` / `SelectTrigger` 后，单测继续按组件类型找节点。渲染结果与复合写法一致。
- **白卡上的字段用 `variant="secondary"`**：HeroUI 的 `primary` 输入变体背景是 `--field-background`（浅色主题下是白色）且边框宽度为 0，放在白色设置卡上等于隐形；`secondary` 是 `--default` 浅灰底，和宿主设置页语言一致。
- **分段控件用 `ToggleButtonGroup` + `ToggleButton`**：Radix `SegmentedControl` 没有对应物；`onSelectionChange` 收到的是 `Set`，取第一个 key 再交给插件原有的更新函数。
- **HeroUI 的 `.card` / `.badge` / `.header` 是全局根类**：插件布局里的原生 div 不能再用这些裸类名，插件自有 class 一律加前缀，否则会悄悄吃到组件样式。
- **插件里不能写 Tailwind utility class**：宿主 Tailwind 只扫描宿主源码，`flex` / `gap-2` 这类工具类不会被生成，布局仍由插件自己的 CSS 负责。
- **旧宿主没有 `__CATRACE_HEROUI__`**：新插件设置页会显式抛错、由宿主显示「设置加载失败」，不做静默降级——降级成原生控件会让界面回到迁移前且更难排查。

## 验证

- 宿主：`CATRACE_PLUGIN_SOURCE=<插件仓库>` 下 `node --test scripts/test-react-plugin-packages.mjs`，用真实 React + 真实 HeroUI 对 15 个插件的 ui/settings 做 SSR 初始渲染与回调断言。
- 插件：各自的 Node 单测（stub `__CATRACE_HEROUI__` 为字符串组件类型）继续覆盖配置读写、RPC、防抖、卸载 flush 等行为。
