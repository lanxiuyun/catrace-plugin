# dsh-chat 四轮：去装饰（把小窗里的官方 GUI 收拾干净）

日期：2026-10-03　插件：`tools/plugin-demo/dsh-chat/`　起因：用户「可以了，但小窗上有很多元素很多余」

## 做了什么

真 GUI 模式加了四个**默认开、可逐项关闭**的去装饰开关（设置页「小窗」区）：
左栏图标栏、对话/轨迹标签、头部动作区（子智能体数/后台任务/角标）、输入区状态条（tok/s、费用、上下文占比）。
另外把我自己那圈卡片外壳瘦成一行（去掉「真 GUI」标签与会话 id 副行，会话 id 收进 tooltip）。

## 关键教训：隐藏左栏不能 `display:none`

第一版尝试 `[class*="_sidebarCol"] { display:none }`，输入框从 261px 变成 **22px**。
导出祖先链才看清：官方是 CSS grid `_1qAH1q_frame { grid-template-columns: 56px 304px 0px }`，
**display:none 让中间列自动落到第一轨（56px）**；而且 React 缓存了测量值，去掉样式也不恢复，
必须整页刷新才复原 —— 这也解释了上一轮"裁剪把布局弄坏"的旧账。

正确做法是保留元素、把轨道归零并把中间列显式钉在第二轨（见 feature 文档里的三段 CSS）。
实测：输入框回到 **317px**、横向溢出 0、正文字数不减。

## 方法（下次别再靠眼睛猜）

1. `e2e-temp/a2-crop-recon.mjs` 把 360×480 下所有带语义 class 的元素导出成 JSON（含 box/text），
   用文本（"缓存命中"/"子智能体"/"对话"/"假日"…）反查语义类名；
2. `e2e-temp/a2-crop-measure2.mjs` **每条规则重新加载页面**再量（第一版没重载，第一条规则的破坏污染了后面全部数值，
   差点得出"所有规则都不安全"的错误结论）；
3. 断言口径固定为三条：输入框宽度不许缩水、`documentElement.scrollWidth - innerWidth === 0`、正文字数不显著减少。

选择器一律用语义后缀（`[class*="_tabs"]`），因为 CSS Module 的哈希每次构建都会变。
