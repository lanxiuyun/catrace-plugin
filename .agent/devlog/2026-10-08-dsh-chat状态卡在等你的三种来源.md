# 2026-10-08 dsh-chat 状态卡「在等你」的三种来源

## 会话目标

修掉用户反馈的「等你审批状态好像没用，一直都是进行中的」。

## 根因

`NoticeTracker` 只有 `approval/asked` 一条进入 waiting 的路径，而本机 v4 日志里
`approval/asked` 一次都没有（`approval/policy` 是 `never`，或 `ask` 但工作区内操作不需要越权）。
用户实际遇到的是官方 `pendingInteraction` 的另外两种：`question`（`ask_user_question`）
与 `plan-review`（`exit_plan_mode`）——它们是瞬态交互，**不写会话事件**，只能靠
「工具 `tool/call` 落盘、`tool/result` 还没回来」在日志里认出来。

## 完成项

- `runtime/lib/inspector.mjs`：新增 `HUMAN_GATE_TOOLS` allowlist + `pendingGates` 登记；
  waiting 的 chip 按原因分「等你审批 / 等你回答 / 计划待审」；`#waitInfo()` / `#settleWaiting()`
  统一「谁在等 → 转什么状态」；新回合作废上一轮的未决登记；等的理由变了会重发一次。
- `runtime/main.mjs`：`publishNotice` 用 `action.label` 当 `statusLabel`，payload 多带 `waitKind`。
- `ui.mjs`：chip 文案优先用 payload 的 `statusLabel`（旧宿主/测试卡则回退状态默认文案）。
- 回归：`inspector.test.mjs` 新增 6 条（提问待答、计划待审、普通工具不算、无 callId 不登记、
  审批与闸门并存、新回合作废孤儿登记），全套 106 条通过。

## 验证

- `node --test runtime/test/*.test.mjs`（Node 24）：106 pass / 0 fail。
- 真机日志回放（`~/.dsh/sessions/**/session.v4.jsonl.zstd`，逐事件增量喂 tracker）：
  补丁前 0 次「等你…」，补丁后 3 次——本次对话 `等你回答@seq506`、
  crazy_label `等你回答@seq461`/`@seq662`，与真实 28s 等待窗口吻合。
- 未在真机 UI 上验收：需要 Catrace 重新打包该插件（或 debug 版 junction）后由用户点一次 DSH 提问。
