# 2026-10-09 dsh-chat 状态卡四态一律常驻（并删掉「完成后停留」）

## 起因

用户先问「报错/等待审批这些状态，小窗能不能常驻不消失？当前是展开过后就不会再消失是吗？」，
确认现状后拍板：**四个状态（进行中 / 等你处理 / 已完成 / 回合失败）全部常驻**。

## 改动前的真实行为（先查代码，别凭印象）

`runtime/lib/inspector.mjs` 的 `#actionFor()` 里原来是一行：

```js
const sticky = state.phase === 'done' || state.phase === 'error' ? expanded : true
```

- `running` / `waiting` → 恒 `sticky: true`（常驻，本来就不消失）；
- `done` / `error` → **只在卡片处于展开态时才常驻**；折叠态下发 `auto_hide_ms = noticeDoneHoldMs`。

所以用户"展开过就不消失"的印象**只对一半**：是"展开**期间**不消失"，点「收起」后
`setExpanded(false)` 会补发一张 `sticky:false + auto_hide_ms` 的卡，宿主
（`src/views/toastWindows/reminder/useToastBusEvents.ts` 在收到 `!sticky` 更新时重新上计时）
到点又把它收掉。

## 改法与连带项

1. `inspector.mjs`：`sticky` 恒为 `true`，`autoHideMs` 字段整体删除；`NoticeTracker` 构造参数
   不再收 `doneHoldMs`。
2. `main.mjs`：`publishNotice` 不再下发 `payload.auto_hide_ms` 与 `doneHoldMs`；
   `noticeStatus` 不再报 `doneHoldMs`；`applyConfig` 里"只同步停留时长"那个分支删掉。
3. **设置页「完成后停留(ms)」整行删除**（`config.mjs` 的 `noticeDoneHoldMs`、
   `settings.mjs` 的 DEFAULTS / LIMITS / NUM_KEYS / 表单初始化一起删）。
   理由：全常驻之后这个值不再影响任何行为，留着就是"设置没用"——
   这类摆设正是用户反复吐槽过的东西。老配置里的该键按**未知字段丢弃**（已加进退场键测试）。
4. 「测试卡」四个按钮（进行中/已完成/等你处理/处理失败）同步改成常驻，
   否则按「处理失败」测不出真实手感——那次专门在 `main.test.mjs` 里断言 `sticky === true`。

## 取舍与已知代价

- 完成/报错卡不再自清，右下角会**按会话累积**（同会话仍是同 `dedupeKey` 原地刷新，不会叠成两张）。
  收场只有两条路：用户点 ×（本轮静默，下一轮解除），或下一轮开始原地换新卡。
- 如果以后嫌堆，正确的补法不是恢复"停留 N 秒"，而是**加一个"完成/报错卡常驻"开关**（默认开）——
  用户可以自己切回自动收。
- 「等你处理」的卡被你手动收起后，不会因为下一次补发又被自动弹开：`autoExpand` 仍然是
  `isWaiting && !expanded`，收起态会写回 sidecar（`POST /notice/view`）。

## 验证

- `node --test "runtime/test/*.test.mjs"` → **118/118 通过**。
- 新增用例「四个状态一律常驻」：把 running/done/error/waiting 四种状态各推一遍，
  断言都 `sticky === true` 且 `autoHideMs === undefined`（漏一个状态就会挂）。
- `main.test.mjs` 的真 sidecar 用例改为：完成卡展开、收起两个方向都断言 `sticky === true`、
  `auto_hide_ms === undefined`，测试卡（done/error）同样断言常驻。
