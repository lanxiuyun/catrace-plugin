# 前往会话：进程链捕获与窗口聚焦

`agent-notify` 卡片底部「前往会话」按钮的完整链路：点击后把**运行该会话的终端/应用窗口**拉到前台。本特性横跨插件（hook / sidecar / UI）与宿主（新 plugin API），两侧知识在此合并记录。

## 交互定案（2026-09-14 grill-me 拍板）

- **跳转语义**：聚焦会话所在窗口（五个 agent 全是终端 CLI，无 Web 会话页；`--resume` 会 fork 新会话，不符合「前往」）。
- **精度上限**：窗口/应用级，不到标签页级（WT 多标签或集成终端只保证窗口置前）。用户环境（conhost 经典窗口 + ZCode 桌面版）不受影响。
- **失败降级**：按钮文案变「未能定位终端窗口」2 秒 + beep，无弹窗。
- **点击范围**：只有按钮触发跳转；正文短文本点击不冒泡（旧 devlog 里的「冒泡到宿主」意图已废弃）。
- **成功后**：自动关闭该会话卡片（emit close）。
- **平台**：Windows 精确实现；macOS/Linux 宿主 API 返回 false，按钮文案降级提示。

## 链路总览

```text
hook.cjs（每次事件）
  注入 catrace_hook_pid / catrace_hook_ppid
  → main.mjs normalizeHookData: hookPpid
  → 会话首事件时异步爬进程祖先链（不阻塞发布），按 `${agentId}:${sessionId}` 缓存
  → entry.pidChain（命中缓存的事件才带，可能缺失）
  → ui.mjs 点击按钮
  → plugin.window.focusExternal(pidChain)   ← 宿主新增 API（plugin_api_window_focus_external）
  → true  → emit('close') 关卡
  → false → 按钮文案 2s「未能定位终端窗口」+ beep
```

## 为什么要爬进程链，为什么必须在 hook 事件时爬

hook 只拿得到直接父 pid（`process.ppid`）。祖先要一次全量进程快照向上爬（Windows 用 PowerShell `Get-CimInstance Win32_Process`，Unix 用 `ps -axo pid=,ppid=`）。

关键约束：**hook 的直接父可能是 CLI 的临时 shell 包装**（如 Claude 用 `cmd /c node hook.cjs`），这个包装进程只在 hook 运行期间存活。如果只把 ppid 传给 sidecar、等用户点击时再爬，中间进程早已死掉，链断了。所以 sidecar 收到会话**首个事件**时立刻爬完缓存；之后的事件直接用缓存（终端进程跨会话存活，链不会失效）。捕获失败做 30 秒负缓存，避免每个事件都拉一次快照（PowerShell 快照 0.5~2s，不能挂在 PostToolUse 上）。

## 宿主侧匹配算法（window_manager/windows.rs）

pid 链由内向外（hook 父进程 → CLI → shell → 终端），匹配两步：

1. **AttachConsole 取控制台窗口**（逐链内进程，由内向外）：经典 conhost 的控制台窗口属主是 conhost.exe——它是 shell 的**子**进程而非祖先，纯祖先匹配永远找不到它。只能 `AttachConsole(pid)` + `GetConsoleWindow()` 取该进程的控制台窗口。ConPTY（Windows Terminal / 集成终端）下取到的是 NULL 或不可见句柄，靠 `IsWindowVisible` 检查自然跳过。
2. **祖先窗口属主匹配**（由外向内遍历 `EnumWindows`）：覆盖 Electron（ZCode 桌面版：链最外层就是 ZCode.exe，直接命中主窗口）和 Windows Terminal（shell 的父进程是 WT.exe）。

附加处理：本进程已有控制台时先 `FreeConsole` 再附加；`IsIconic` 最小化先 `SW_RESTORE`；跳过 pid 0 与自身；前置复用 toast 窗口激活的 `force_foreground_window`（AttachThreadInput 三件套）。

## 缓存与生命周期

- `pidChainCache`：内存 Map，**不落盘**——sidecar 重启后链缓存丢失，下一个 hook 事件会重新爬（那时 hook 还活着，链仍可爬），自愈。
- 容量 500，超出时淘汰最早一半（会话数远达不到）。
- `pidChainFailAt`：失败负缓存 30s，防止反复拉快照。
- 卡片在链就绪前发布则 `entry.pidChain` 缺失；就绪后**不重发卡片**，同会话下一个事件自然带上。极小窗口期（首事件即 sticky 且快照慢且用户秒点）会看到失败文案，属预期。

## 宿主 API 契约

- `plugin.window.focusExternal(pidChain: number[]): Promise<boolean>`（主仓 `src/plugins/pluginApi.ts`）
- 命令 `plugin_api_window_focus_external`（主仓 `src-tauri/src/plugin_api/window.rs`），`#[cfg]` 隔离：Windows 走 `window_manager::focus_external_pid_chain`，其他平台返回 false。
- Cargo 新增 `windows` crate feature：`Win32_System_Console`。
