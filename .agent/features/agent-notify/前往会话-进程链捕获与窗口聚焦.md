# 前往会话：进程链捕获与窗口聚焦

`agent-notify` 卡片底部「前往会话」按钮的完整链路：点击后恢复并显示**运行该会话的应用或终端窗口**。进程识别与 Windows 窗口操作都由插件 Node sidecar 完成，宿主只提供现有的本机 HTTP 调用能力。

## 交互定案（2026-09-14 grill-me 拍板）

- **跳转语义**：优先恢复 ZCode、Cursor、VS Code、Codex 等 App 窗口；没有 App 候选时再恢复 Windows Terminal、PowerShell、cmd、conhost 等 terminal 窗口。
- **精度上限**：窗口/应用级，不到标签页级。命中同一最高优先级类别的多个窗口时全部恢复显示。
- **成功标准**：至少一个目标 HWND 经 `SW_SHOW` / `SW_RESTORE` 后可见；foreground 仅 best-effort，不作为成功条件。
- **失败降级**：按钮文案变「未能定位终端窗口」2 秒 + beep，无弹窗。
- **点击范围**：只有按钮触发跳转；正文短文本点击不冒泡。
- **成功后**：自动关闭该会话卡片（emit close）。
- **平台**：Windows 实现；macOS/Linux 返回失败。

## 链路总览

```text
hook.cjs（每次事件）
  注入 catrace_hook_pid / catrace_hook_ppid
  → main.mjs normalizeHookData: hookPpid
  → 会话首事件时异步爬进程祖先链（不阻塞发布），按 `${agentId}:${sessionId}` 缓存
  → entry.pidChain（命中缓存的事件才带，可能缺失）
  → ui.mjs 点击按钮，携带 hookPpid + pidChain
  → plugin.http.get(http://127.0.0.1:23456/focus?pids=...)
  → sidecar focus-windows.mjs 扩展祖先进程并分类窗口
  → ok=true  → emit('close') 关卡
  → ok=false → 按钮文案 2s「未能定位终端窗口」+ beep
```

## 为什么要爬进程链，为什么必须在 hook 事件时爬

hook 只拿得到直接父 pid（`process.ppid`）。祖先要一次全量进程快照向上爬（Windows 用 PowerShell `Get-CimInstance Win32_Process`，Unix 用 `ps -axo pid=,ppid=`）。

关键约束：**hook 的直接父可能是 CLI 的临时 shell 包装**（如 Claude 用 `cmd /c node hook.cjs`），这个包装进程只在 hook 运行期间存活。如果只把 ppid 传给 sidecar、等用户点击时再爬，中间进程早已死掉，链断了。所以 sidecar 收到会话**首个事件**时立刻爬完缓存；之后的事件直接用缓存（终端进程跨会话存活，链不会失效）。捕获失败做 30 秒负缓存，避免每个事件都拉一次快照（PowerShell 快照 0.5~2s，不能挂在 PostToolUse 上）。

## Sidecar 匹配算法（focus-windows.mjs）

sidecar 会再次从输入 PID 向上扩展祖先进程，按以下优先级选择第一个存在有效窗口的类别：

1. **App**：ZCode、Codex、Claude、VS Code、Cursor、Trae、Windsurf、Kiro。
2. **Terminal App**：Windows Terminal、WezTerm、Alacritty、Kitty、Tabby、Wave。
3. **经典 console**：对 PowerShell、pwsh、cmd、conhost 对应进程执行 `AttachConsole` + `GetConsoleWindow`。
4. **其他应用**：祖先链中未被排除、拥有带标题顶层窗口的进程。

直接枚举的 App/terminal 窗口只接受**有标题且无 owner**的顶层 HWND，并排除 `OleDdeWndClass`，避免把 Claude 的 `DDE Server Window`、Electron 的 IME 等内部窗口恢复出来。选中类别后，对该类别全部候选执行 `SW_SHOW` 和 `SW_RESTORE`；任一窗口随后可见即为成功。第一个成功窗口会 best-effort 调用 `SetForegroundWindow`，但不校验 foreground。

## 缓存与生命周期

- `pidChainCache`：内存 Map，**不落盘**——sidecar 重启后链缓存丢失，下一个 hook 事件会重新爬（那时 hook 还活着，链仍可爬），自愈。
- 容量 500，超出时淘汰最早一半（会话数远达不到）。
- `pidChainFailAt`：失败负缓存 30s，防止反复拉快照。
- 首个 `/state` 请求会等待进程链快照完成后再返回；hook 在等待期间保持存活，因此 `process.ppid` 指向的短命 shell 包装不会先退出。状态 hook 内部 HTTP timeout 为 8 秒，Claude/ZCode 外层 command hook timeout 为 15 秒。卡片第一次发布时就带完整 `pidChain`，无需二次发布或修改宿主 Event Bus。

## HTTP 契约

- UI 调用 `plugin.http.get("http://127.0.0.1:23456/focus?pids=<comma-separated>")`。
- sidecar 返回 `{ ok, category, restored, candidates }`。
- `ok` 只表示至少一个窗口已恢复可见；UI 收到 `ok: true` 后关闭卡片。
