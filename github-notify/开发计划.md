# github-notify 插件开发计划

## 目标

GitHub 通知提醒插件：轮询 GitHub Notifications API，把新通知（PR/Issue/讨论/提交）以通知卡片推送到 Catrace 弹窗。仅在用户活跃时推送。支持配置轮询间隔、卡片停留秒数（默认 10 秒）。

## 背景 / 已知约束

- 插件目录：`plugins/github-notify/`（当前为空）
- 参考现有插件：timer（background.mjs + plugin.activity）、sidecar-echo（sidecar JSONL 最简实现）、bt-music（sidecar 完整样本 + manifest sidecar 字段）
- 插件 API：`plugin.config / plugin.storage / plugin.events.publish / plugin.activity / plugin.log / plugin.http / plugin.sidecar / plugin.setEnabled`
- 活跃检测：`plugin.activity.get()` 返回 `{ active: bool }`；另有 `plugin.activity.getLastRealRest()`
- sidecar 协议：
  - stdout JSONL `{v:1, op:'ready'|'publish'|'log'|'response', ...}`
  - stdin 接收 `{op:'shutdown'|'config'|'request'|'resolved', ...}`
  - 环境变量 `CATRACE_PLUGIN_ID`、`CATRACE_PROTOCOL_VERSION`
- 事件字段：`eventType / kind / title / body / level / sticky / actions / payload / dedupeKey`
  - payload 中 `auto_hide_ms` 由宿主驱动自动隐藏（timer 卡片用 CSS 变量 `--toast-auto-hide-ms`）
- 配置持久化：`settings.json`，键 `plugin_config:<id>`
- GitHub API：`GET https://api.github.com/notifications`，需请求头 `Authorization: Bearer <PAT>` 与 `Accept: application/vnd.github+json`

## 关键技术决策

1. **sidecar（Node fetch）+ background（活跃门控）**
   - 原因：`plugin.http.get()` 不支持自定义请求头；Node `fetch` 可带 `Authorization`
   - sidecar 只负责轮询/去重/pending 队列；background 调 `plugin.activity.get()` 后 `drainPending` 再 publish
   - manifest 声明 `sidecar` + `background`

2. **轮询去重**
   - 用 `plugin.storage` 不可行（sidecar 无 plugin 对象），改用本地 state 文件或内存 + 启动播种
   - 方案：首次启动只做基线快照不推送；后续轮询用 GitHub 返回的 `id` 集合做增量，新 id 才 publish；用 `Last-Modified` 头 + 本地已见 id 集优化请求
   - 实现细节：本地 `runtime/main.mjs` 内存保存 `seenIds`，启动时先拉一次记为基线；跨重启丢内存问题：把 seen ids 存到临时文件或接受重启后重推一次的代价（重推可能重复打扰，建议用文件持久化，简单可靠）

3. **活跃门控**
   - sidecar 内无法调用 `plugin.activity`（那是宿主注入的对象，仅 background/ui/settings 可见）
   - 方案 A：sidecar 发 `request` op 向宿主查询活跃状态 —— bt-music 已实现 request/response 通道，可行
   - 方案 B：由 background.mjs 周期读取活跃状态转发给 sidecar —— 复杂度高
   - 结论：用方案 A，sidecar 通过 `{op:'request', method:'getActivity'}` 查询，宿主返回 `{ok:true, result:{active}}`

## 文件结构

```
github-notify/
├── manifest.json        # 插件声明，sidecar 配置
├── settings.mjs         # 设置页：Token / 轮询间隔 / 停留秒数 / 活跃开关
├── ui.mjs               # 通知卡片：仓库名 + 标题 + 类型 + 时间 + 跳转链接
└── runtime/
    └── main.mjs         # sidecar：Node fetch 轮询 + 去重 + 活跃门控 + publish
```

## 配置项（settings.mjs ↔ sidecar config）

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `token` | string | '' | GitHub PAT（只读通知权限即可） |
| `pollIntervalSec` | number | 60 | 轮询间隔（秒） |
| `cardDurationSec` | number | 10 | 卡片停留秒数，0 = 常驻 |
| `onlyWhenActive` | bool | true | 仅用户活跃时推送 |
| `enabled` | bool | true | 插件总开关 |

## 实施步骤

1. 写 `runtime/main.mjs`：
   - 启动 `ready` → 拉一次基线（记录 Last-Modified + seen ids）不推送
   - `setInterval` 轮询；有 Authorization 头才拉；401 记 warn
   - 增量新通知 → 查宿主活跃状态 → 活跃则 publish，不活跃则记录 pending（下次活跃后再推或丢弃，见下）
   - 收 `config` 重设 interval / token / 活跃开关；收 `shutdown` 退出；收 `resolved` 记日志
2. 写 `manifest.json`（id `github-notify`，events 含 `["github-notify", "kind:github-notify", "github-notify.notification"]`）
3. 写 `settings.mjs`：Token 输入框 + 数字输入 + NSwitch 开关
4. 写 `ui.mjs`：渲染通知卡片，带「打开」按钮跳转 `html_url`（用 `plugin.shell.openExternal` 或卡片 action）
5. `node --check` 校验各 .mjs

## 待确认 / 风险

- [ ] sidecar `request` op 是否真能查到活跃状态（bt-music 未用 getActivity；timer 只在 background 用）→ 若不行，降级为：publish 时不门控，由宿主 toast 层级自然处理；或 sidecar 只拉数据、background.mjs 负责活跃判断后 publish（改回 background 方案）
- [ ] `plugin.shell.openExternal` 是否存在于注入 facade（sidecar-echo settings 用过，确认 UI 侧可用）
- [ ] GitHub API 未认证时返回 401；Token 缺失时轮询应跳过且不刷屏日志
